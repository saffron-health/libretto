> Receive portal SMS one-time codes through tenant-owned Libretto Cloud inbox numbers, then wait for the code inside a workflow.

SMS OTP is for portals that text a code to a phone number. Prefer authenticator TOTP (`*_totp_secret`) when the portal supports it.

## How it works

1. Provision an inbox number into your tenant pool (CLI or dashboard).
2. Register that full phone number (with country code, like `+15551234567`) as the MFA phone on the portal account.
3. In the workflow: open a claim, click send-code, then `waitForSmsOtp` polls Libretto Cloud until the inbound SMS is written to the claim.

Use **one phone number per portal** (or per portal login). Do not run concurrent SMS OTP waits on the same inbox number. A claim locks the inbox for up to 5 minutes; pulling the code unlocks it, and a new claim can take over after the lock expires.

## Configure numbers (outside workflows)

```bash
libretto cloud sms-numbers provision --label uhc
libretto cloud sms-numbers list
```

Dashboard: **Phone numbers**. Copy the phone number (with country code) and set it on the portal MFA settings.

### POST `/v1/smsNumbers/provision`

Requires `x-api-key`.

Request fields:

- `label` (optional): portal label such as `uhc`
- `country` (optional): two-letter country code
- `area_code` (optional): preferred area code

### POST `/v1/smsNumbers/list`

Lists pool numbers. Pass `include_released: true` to include released rows.

### POST `/v1/smsNumbers/update`

Update a number's `label`.

### POST `/v1/smsNumbers/release`

Release the number and remove it from your tenant pool. Irreversible.

## Wait for a code in a workflow

```typescript
import { waitForSmsOtp, workflow } from "libretto";

export default workflow("portal-login", {
  credentials: ["username", "password"],
  async handler(ctx, input) {
    // ... fill username/password, then:
    const wait = waitForSmsOtp({
      label: "uhc",
      // Deployed jobs: pass the injected cloud auth blob
      cloud: (input as { __libretto?: { smsOtp?: { apiUrl: string; token: string; jobId: string } } }).__libretto,
      // Local runs: omit cloud and use LIBRETTO_API_KEY
    });

    await ctx.page.click('button:has-text("Send code")');
    const { code } = await wait;
    await ctx.page.fill('input[name="otp"]', code);
  },
});
```

`waitForSmsOtp` calls:

1. `POST /v1/smsOtp/claims/create` — exclusive open claim on the inbox
2. `POST /v1/smsOtp/claims/get` — poll until fulfilled, then consume the code once

Deployed jobs receive a short-lived `input.__libretto.smsOtp` token at dispatch. Local runs use `LIBRETTO_API_KEY`.

### Claim routes

Both accept `x-api-key` or `x-libretto-sms-otp-token`.

**Create** — `number_id`, `label`, or `phone_number`; optional `job_id`, `ttl_seconds` (30–300, default 300). `waitForSmsOtp` sets `ttl_seconds` from `timeoutMs` and does not expose a separate TTL option.

**Get** — `claim_id`; optional `consume` (default true). Returns `code` once when fulfilled.

## Isolation rules

- Numbers are tenant-scoped (RLS).
- Inbound SMS is matched to the inbox number that received it.
- At most one open claim per number (HTTP 409 if busy). Create expires stale open locks (≥5 minutes) before taking the lock.
- Codes are encrypted at rest, single-consume, and treated as secrets in log sanitization.
