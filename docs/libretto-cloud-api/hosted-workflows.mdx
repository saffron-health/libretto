> Search, run, and save opaque workflows published by other Libretto Cloud tenants.

Hosted workflow commands require `LIBRETTO_API_KEY`. The API key's tenant owns
each run and bookmark. Publishers do not receive access to the caller's tenant,
credentials, or results.

### CLI

Search the public catalogue and inspect a workflow before running it:

```bash
libretto cloud hosted-workflows search eligibility
libretto cloud hosted-workflows get acme/check-eligibility
```

Start a run with input parameters and references to credentials already stored
in your Libretto Cloud tenant:

```bash
libretto cloud hosted-workflows run acme/check-eligibility \
  --params '{"member_id":"123"}' \
  --credentials '{"portal_login":"payer-portal"}'
```

The command returns a job ID. Poll once or wait until it reaches a terminal
state:

```bash
libretto cloud hosted-workflows status <job-id>
libretto cloud hosted-workflows status <job-id> --watch
```

Save a workflow with an optional alias, notes, and non-secret defaults:

```bash
libretto cloud hosted-workflows save acme/check-eligibility \
  --alias eligibility \
  --notes "Default west region" \
  --defaults '{"region":"west"}'

libretto cloud hosted-workflows saved
libretto cloud hosted-workflows run eligibility --params '{"member_id":"123"}'
libretto cloud hosted-workflows remove <bookmark-id>
```

Explicit run parameters override saved defaults. Use `--json` on any command
for machine-readable output. Commands that accept JSON also accept the matching
file option, such as `--params-file`, `--credentials-file`, or
`--defaults-file`.

Do not put secret values in params or bookmark defaults. The `--credentials`
map contains stored credential IDs or names, not raw secrets.

### HTTP routes

All routes require `x-api-key`.

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/v1/hosted-workflows?q=<query>&limit=<limit>` | Search the catalogue. |
| `GET` | `/v1/hosted-workflows/:publisher/:workflow` | Inspect one workflow. |
| `POST` | `/v1/hosted-workflows/run/:publisher/:workflow` | Queue a run. |
| `GET` | `/v1/hosted-workflows/bookmarks` | List tenant bookmarks. |
| `POST` | `/v1/hosted-workflows/bookmarks` | Save or update a bookmark. |
| `DELETE` | `/v1/hosted-workflows/bookmarks/:id` | Remove a bookmark. |

Poll run results with `POST /v1/jobs/get`. See
[Jobs and logs](/libretto-cloud-api/jobs-and-logs) for the response fields.

The bookmark save body uses this shape:

```json
{
  "workflow": "acme/check-eligibility",
  "alias": "eligibility",
  "notes": "Default west region",
  "default_params": {
    "region": "west"
  }
}
```

If a publisher unhosts a workflow or disables code sharing, the bookmark stays
in the tenant's saved list and becomes unavailable. Libretto does not return
the disabled publication's schemas and will not run it.
